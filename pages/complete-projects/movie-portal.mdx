## Step 1: Movie Portal আসলে কী জিনিস? 🎥

কোনো প্রজেক্টে হাত দেওয়ার আগে সবচেয়ে জরুরি কাজটা হলো — **ডোমেইন বোঝা**। মানে, যে প্রোডাক্টটা আমরা বানাতে যাচ্ছি, _বাস্তবে সেটা কী এবং কীভাবে কাজ করে_ — এটা না বুঝে কোড লিখতে বসা মানে স্ক্রিপ্ট না পড়েই শুটিং শুরু করে দেওয়া।

**"Movie Portal"** শব্দটা শুনলে সাধারণত যা মাথায় আসে তা হলো:

> এমন একটি ওয়েবসাইট বা অ্যাপ, যেখানে ব্যবহারকারীরা সিনেমা খুঁজে দেখতে পারে, তথ্য জানতে পারে, ট্রেলার দেখতে পারে — এবং কখনো কখনো রেন্ট বা স্ট্রিমও করতে পারে।

টেকনিক্যাল ভাষায় বললে, এটা একটা **content-catalog application** — যার মূল কাজ হলো একটা structured dataset (মুভি ক্যাটালগ)-কে browsable, searchable আর interactive UI-তে রূপান্তর করা। একজন React developer হিসেবে আপনি যদি একটা ভালো content catalog architecture বুঝে ফেলেন, তাহলে অনেক ধরনের app বানানোর base তৈরি হয়ে যায়। এর তিনটা মূল বিল্ডিং ব্লক:

- একটা **data layer**, যেখানে অনেকগুলো সিনেমার মেটাডেটা (নাম, পোস্টার, রেটিং, ভিউ, প্রাইস) জমা থাকে।
- একটা **discovery layer**, যেখানে ইউজার সার্চ আর ফিল্টার করতে পারে।
- একটা **detail/interaction layer**, যেখানে একটা নির্দিষ্ট আইটেমের ডিটেইলস দেখা যায়, আর অ্যাকশন (যেমন কার্টে যোগ করা) নেওয়া যায়।

**চেনা উদাহরণ:** Netflix একটা Movie Portal (সাথে Streaming Service-ও বটে)। IMDB আরেকটা — যেখানে তথ্য, ট্রেলার, রেটিং, রিভিউ সব এক জায়গায়।

🔵 তাহলে কেউ যদি বলে "Movie Portal Website বানাও" — সহজ ভাষায় এর মানে দাঁড়ায়:

> এমন একটা ওয়েবসাইট, যেখানে অনেক সিনেমার তথ্য থাকবে, আর মানুষ সহজেই নিজের পছন্দের সিনেমা খুঁজে নিতে পারবে।

আমরা এই টিউটোরিয়ালে যেটা বানাবো, সেটা একটু স্পেসিফিক — একটা **Cinema Rental Portal**। মানে মুভি ব্রাউজ করা, ডিটেইলস দেখা, আর একটা Cart-ভিত্তিক rental flow পার হয়ে যাওয়া।

## Step 2: কোড লেখার আগে — স্ক্রিপ্ট রেডি করুন 📝

বড় ডিরেক্টররা শুটিং শুরু করার আগে পুরো স্ক্রিপ্ট, স্টোরিবোর্ড, শট-লিস্ট রেডি রাখেন। প্রোগ্রামিংয়েও ঠিক একই নিয়ম — কোড লেখার আগে **Requirement Analysis** আর **System Design** না করলে, পরে গিয়ে Component re-architecture, state management জট আর technical debt-এর পাহাড় জমে যায়। আর বিশ্বাস করুন, মাঝপথে পুরো সেট ভেঙে আবার বানানোর চেয়ে কষ্টের আর কিছু নেই।

### ১. প্রজেক্টের স্কোপ ঠিক করুন

- **App-এর উদ্দেশ্য কী?** (মুভি ব্রাউজ করা, রেটিং দেখা, সার্চ করা, কার্টে যোগ করে রেন্ট করা)
- **দর্শক কারা?** কোন বয়সের, কোন ডিভাইস থেকে আসবে — মোবাইল-ফার্স্ট নাকি ডেস্কটপ-ফার্স্ট?
- **Functional Requirements** — অ্যাপ আসলে কী কী করতে পারবে।
- **Non-Functional Requirements** — পারফরম্যান্স, রেসপনসিভনেস, অ্যাক্সেসিবিলিটি।

### ৬. Data Flow / State Planning

প্রতিটা React প্রজেক্টে State-কে তিন ভাগে ভাগ করে ভাবা উচিত:

- **Local UI State** — শুধু একটা কম্পোনেন্টের ভেতরে দরকার (যেমন: dropdown খোলা আছে কিনা)। `useState` দিয়ে সামলানো যায়।
- **Shared/Global State** — একসাথে একাধিক, দূরে দূরে থাকা কম্পোনেন্টের দরকার (Cart Items, Active Theme)। এখানে আমরা **Context + Reducer** প্যাটার্ন ব্যবহার করব, যাতে prop drilling এড়ানো যায়।
- **Derived State** — অন্য state থেকে হিসাব করে বের করা যায় এমন ভ্যালু, যেমন কার্টের মোট দাম। এগুলোকে আলাদা state হিসেবে না রেখে render-এর সময় calculate করাই ভালো অভ্যাস।

### ৭. Routes Planning (React Router)

কোন পেজে কী থাকবে, তার একটা ম্যাপ থাকা দরকার — Modal-based UI হলেও। কারণ deep-linking (সরাসরি একটা URL শেয়ার করে নির্দিষ্ট মুভির ডিটেইলস বা কার্ট খুলে যাওয়া) একটা সলিড UX প্র্যাকটিস।

_(Route map: `/`, `/movies/:id` — `:id` থাকলে Movie Details Modal URL থেকেই খুলে যাবে, `/cart`)_

এই রাউটিং আমরা পরে **React Router v8** দিয়ে বসাবো (এখন প্যাকেজের নাম শুধু `react-router` — আলাদা করে `react-router-dom` ইন্সটল করার দরকার নেই)।

### ৩. Context API — Prop Drilling-এর যন্ত্রণা থেকে মুক্তি

**Context API** হলো React-এর বিল্ট-ইন State Management সলিউশন। যখন অনেকগুলো Component-এর একই Data দরকার হয়, তখন এটাই বাঁচায়।

সাধারণত Parent থেকে Child-এ Data পাঠাতে গেলে বারবার Props পাস করতে হয় — একে বলে **Prop Drilling**, আর এটা যত গভীরে যায়, কোড তত এলোমেলো হয়ে ওঠে। Context API এই সমস্যার সমাধান।

আমাদের Movie Portal-এ Context API দিয়ে যা যা গ্লোবালি রাখব:

- Cart Items ও Cart Actions
- Theme Settings (Light/Dark)
- Selected Movie (Modal-এর জন্য)
- Favorite Movies
- Authentication Status

```text
Context Provider
      │
      ▼
Multiple Components
      │
      ▼
Access Shared Data via useContext()
```

ফলে যেকোনো Component প্রপ-চেইন না ভেঙেই সরাসরি দরকারি Data অ্যাক্সেস করতে পারে।

### ৪. Reducer Pattern (useReducer) — জটিল State-কে শৃঙ্খলায় আনা

**Reducer Pattern**-এ Complex State Logic একটা আলাদা pure function-এর হাতে তুলে দেওয়া হয়। React-এর `useReducer` Hook দিয়ে এটা implement করা হয়, আর এর মূল আইডিয়া Redux থেকেই ধার করা — `State + Action + Reducer Function`।

Cart-এর জন্য আমাদের State shape ও Action:

```javascript
const initialCartState = {
  items: [], // [{ id, title, poster, price, qty }]
};
```

Action:

```javascript
{
  type: "ADD_TO_CART",
  payload: movie,
}
```

Reducer:

```javascript
function cartReducer(state, action) {
  switch (action.type) {
    case "ADD_TO_CART": {
      const alreadyExists = state.items.some(
        (item) => item.id === action.payload.id,
      );
      if (alreadyExists) {
        return state; // duplicate হলে state অপরিবর্তিত থাকবে, UI warning দেখাবে
      }
      return {
        ...state,
        items: [...state.items, { ...action.payload, qty: 1 }],
      };
    }

    case "REMOVE_FROM_CART":
      return {
        ...state,
        items: state.items.filter((item) => item.id !== action.payload.id),
      };

    default:
      return state;
  }
}
```

Reducer ব্যবহারের সুবিধা:

✅ Complex State Logic ম্যানেজ করা সহজ
✅ State Update Predictable হয় (pure function — same input, same output সবসময়)
✅ Code Scalable হয়
✅ Large Application Maintain করা সহজ হয়

এই প্রজেক্টে **Component Architecture + Context API + Reducer Pattern** — এই তিনের মিশেলেই আমরা বানাবো একটা Scalable, Maintainable Movie Portal। এখন চলুন, এটাকে সত্যি সত্যি কোডে রূপ দেওয়া যাক — Step 3।

### ধাপ ২: Tailwind CSS v4 — কনফিগারেশনের নতুন নিয়ম

Tailwind CSS v4 একদম গ্রাউন্ড-আপ রিরাইট — এখন এটি Lightning CSS (Rust-based parser/transformer)-এর উপর দাঁড়ানো। সবচেয়ে বড় পরিবর্তন: **`tailwind.config.js` ফাইল আর লাগে না!** কনফিগারেশন এখন সরাসরি CSS ফাইলে `@theme` ডিরেক্টিভ দিয়ে হয় (CSS-first configuration), যা design token গুলোকে native CSS custom properties হিসেবে এক্সপোজ করে দেয়।

প্রথমে first-party Vite প্লাগিনসহ ইন্সটল করুন:

```bash
npm install tailwindcss @tailwindcss/vite
```

`vite.config.js`-এ প্লাগিন যোগ করুন:

```js
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  plugins: [react(), tailwindcss()],
});
```

এরপর `src/index.css`-এ একটা ইম্পোর্ট লাইন আর কাস্টম থিম টোকেন যোগ করুন:

```css
@import "tailwindcss";

@theme {
  /* কাস্টম কালার — আমাদের ডিজাইন সিস্টেম টোকেন */
  --color-primary: #ff0000;
  --color-secondary: #00ff00;

  /* কাস্টম ফন্ট ও স্পেসিং স্কেল-ও এখানেই যোগ করা যাবে */
  --font-display: "Hind Siliguri", sans-serif;
}

/* Dark mode variant — v4-তে darkMode আর JS config-এ থাকে না */
@custom-variant dark (&:where(.dark, .dark *));
```

মজার ব্যাপার হলো — `--color-primary` ডিফাইন করার সাথে সাথেই Tailwind নিজে থেকে `bg-primary`, `text-primary`, `border-primary` ইত্যাদি ক্লাস জেনারেট করে দেয়। আলাদা করে `colors: { primary: ... }` লিখে extend করার দরকারই নেই।

> **Container utility কাস্টমাইজেশন:** v3-তে `container: { center: true, padding: "2rem" }` যেভাবে JS অবজেক্টে লেখা হতো, v4-তে সেটা `@utility` ডিরেক্টিভ দিয়ে override করতে হয়:

```css
@utility container {
  margin-inline: auto;
  padding-inline: 2rem;
}
```

> v4 দ্রুত evolve করছে, তাই সর্বশেষ সিনট্যাক্সের জন্য অফিসিয়াল Tailwind CSS ডকুমেন্টেশন একবার চেক করে নেওয়াই বুদ্ধিমানের কাজ।

### ধাপ ৩: HTML Template থেকে JSX — অনুবাদের নিয়মকানুন

HTML markup-কে JSX-এ রূপান্তরের সময় কিছু সিনট্যাক্স নিয়ম মনে রাখতে হয়, কারণ JSX আসলে HTML নয় — এটা JavaScript-এরই সিনট্যাক্টিক সুগার (পেছনে গিয়ে `React.createElement()` কলে কম্পাইল হয়):

- **`class` → `className`** (কারণ `class` JavaScript-এর reserved keyword)
- **`for` → `htmlFor`** (লেবেল এলিমেন্টে)
- **inline `style`** স্ট্রিং না হয়ে JavaScript object হবে, প্রপার্টি নেম camelCase: `style={{ backgroundColor: "#000", marginTop: "10px" }}`
- সব **attribute camelCase**: `onclick` → `onClick`, `tabindex` → `tabIndex`, `readonly` → `readOnly`
- **Self-closing void elements**: `<img>`, `<input>`, `<br>` অবশ্যই self-close করতে হবে — `<img src="..." />`
- **Comment syntax**: HTML কমেন্ট (`<!-- -->`)-এর বদলে `{/* comment */}`
- **JavaScript expression embedding**: কার্লি ব্রেস `{}` দিয়ে dynamic ভ্যালু বসানো হয় — `<h1>{movie.title}</h1>`
- **একটাই root element**: প্রতিটা কম্পোনেন্ট একটা single root return করবে — বাড়তি wrapper `<div>` এড়াতে `<>...</>` (Fragment) ব্যবহার করা যায়
- **List rendering-এ `key` prop**: `.map()` দিয়ে লুপ করার সময় প্রতিটা child-এ ইউনিক `key` দিতেই হবে — `movies.map((m) => <MovieCard key={m.id} movie={m} />)`

**Assets ও আইকন মাইগ্রেশন:**

HTML template-এর `assets/images`, `assets/fonts`, `assets/icons` ফোল্ডারগুলো `src/assets`-এ কপি করুন। Vite-এ দুই রকম asset handling আছে:

1. **`src/assets`**-এ রাখা ফাইল `import` করে ব্যবহার করতে হয় — Vite এগুলোকে build-time-এ hash করে, optimize করে bundle-এ ঢুকিয়ে দেয়:

   ```jsx
   import heroBanner from "../assets/images/hero-banner.jpg";

   <img src={heroBanner} alt="Hero banner" />;
   ```

2. **`public/`** ফোল্ডারের ফাইল প্রসেস হয় না, সরাসরি root path দিয়ে রেফার করা হয় (favicon, robots.txt ইত্যাদি)।


কম্পোনেন্ট বানানোর সময় আমরা কিছু নীতি মাথায় রাখব:

- **Single Responsibility** — প্রতিটা কম্পোনেন্ট একটাই কাজ করবে (`MovieCard` শুধু একটা মুভির কার্ড দেখাবে, cart logic তার দায়িত্ব না)।
- **Composition over prop drilling** — গভীর component tree-তে বারবার props না পাঠিয়ে Context API ব্যবহার।
- **Presentational vs Container split** — `MovieCard` শুধু UI দেখাবে (presentational), আর actual cart action আসবে `useCart()` hook থেকে (container logic হুকে বন্দি)।
- React 19.2-এর **React Compiler** (এখনো opt-in, `@vitejs/plugin-react` v6-এর সাথে babel/Oxc প্রিসেট দিয়ে এনাবল করা যায়) কম্পোনেন্টগুলোকে অটোমেটিক্যালি মেমোয়াইজ করে দেয় — ফলে বেশিরভাগ ক্ষেত্রে ম্যানুয়ালি `useMemo`/`useCallback` ছড়িয়ে দেওয়ার দরকার কমে আসে। তবে এটা এখনো maturing স্টেজে, তাই প্রোডাকশনে এনাবল করার আগে নিজের লাইব্রেরিগুলোর কম্প্যাটিবিলিটি একবার যাচাই করে নিন।

একে একে এই কম্পোনেন্টগুলো বানাবো: `Navbar`, `MovieCard`, `MovieGrid`, `MovieDetailsModal`, `Cart`, `Footer` — এবং প্রতিটা বানানোর পর `App.jsx`-এ জোড়া লাগিয়ে পেজ অ্যাসেম্বল করব।

### ধাপ ৬: CartContext ও useReducer দিয়ে Cart সিস্টেম

Step 2-এ প্ল্যান করা Reducer Pattern এখন বাস্তবে নামাবো। `cartReducer`-কে আলাদা ফাইলে রাখব, যাতে logic আর Context configuration আলাদা থাকে (separation of concerns):

```js
// src/context/cartReducer.js
export const initialCartState = { items: [] };

export function cartReducer(state, action) {
  switch (action.type) {
    case "ADD_TO_CART": {
      const exists = state.items.some((item) => item.id === action.payload.id);
      if (exists) return state; // duplicate হলে warning component লেভেলে দেখাব
      return { items: [...state.items, action.payload] };
    }

    case "REMOVE_FROM_CART":
      return {
        items: state.items.filter((item) => item.id !== action.payload.id),
      };

    case "CLEAR_CART":
      return { items: [] };

    default:
      return state;
  }
}
```

```jsx
// src/context/CartContext.jsx
import { createContext, useContext, useReducer, useMemo } from "react";
import { cartReducer, initialCartState } from "./cartReducer";

const CartContext = createContext(null);

export function CartProvider({ children }) {
  const [state, dispatch] = useReducer(cartReducer, initialCartState);

  // Derived state — মোট দাম ও আইটেম সংখ্যা আলাদা state হিসেবে না রেখে calculate করছি
  const totalPrice = useMemo(
    () => state.items.reduce((sum, item) => sum + item.price, 0),
    [state.items],
  );

  const value = {
    items: state.items,
    totalPrice,
    itemCount: state.items.length,
    addToCart: (movie) => dispatch({ type: "ADD_TO_CART", payload: movie }),
    removeFromCart: (id) =>
      dispatch({ type: "REMOVE_FROM_CART", payload: { id } }),
    clearCart: () => dispatch({ type: "CLEAR_CART" }),
    isInCart: (id) => state.items.some((item) => item.id === id),
  };

  return <CartContext.Provider value={value}>{children}</CartContext.Provider>;
}

export function useCart() {
  const context = useContext(CartContext);
  if (!context) throw new Error("useCart must be used within a CartProvider");
  return context;
}
```

`MovieCard`-এ duplicate-add হলে ওয়ার্নিং দেখানোর জন্য `isInCart` চেক করে কন্ডিশনালি মেসেজ দেখাবো:

```jsx
// src/components/movies/MovieCard.jsx
import { ShoppingCart } from "lucide-react";
import { useCart } from "../../context/CartContext";
import { formatPrice } from "../../lib/formatPrice";

export function MovieCard({ movie }) {
  const { addToCart, isInCart } = useCart();
  const alreadyAdded = isInCart(movie.id);

  function handleAddToCart() {
    if (alreadyAdded) {
      alert(`"${movie.title}" আগে থেকেই কার্টে যুক্ত আছে।`); // প্রোডাকশনে toast notification ব্যবহার করা ভালো
      return;
    }
    addToCart(movie);
  }

  return (
    <div className="rounded-lg border border-secondary/20 p-4">
      <img src={movie.poster} alt={movie.title} className="rounded-md" />
      <h3 className="mt-2 font-display font-semibold">{movie.title}</h3>
      <p className="text-sm text-secondary">⭐ {movie.rating}</p>
      <button
        onClick={handleAddToCart}
        className="mt-3 flex items-center gap-2 rounded-md bg-primary px-3 py-2 text-white"
      >
        <ShoppingCart size={16} />
        {formatPrice(movie.price)}
      </button>
    </div>
  );
}
```

### ধাপ ৭: MovieDetailsModal — ক্লোজ আপ শট

মুভি কার্ডে ক্লিক করলে যে modal খুলবে, সেটাকে DOM hierarchy-তে `MovieCard`-এর ভেতরে নেস্টেড না রেখে `createPortal` দিয়ে সরাসরি `document.body`-এর চাইল্ড হিসেবে রেন্ডার করাই বুদ্ধিমানের কাজ — এতে `overflow: hidden` বা `z-index` stacking context-জনিত হ্যাপা এড়ানো যায়:

```jsx
// src/components/movies/MovieDetailsModal.jsx
import { createPortal } from "react-dom";
import { useEffect } from "react";
import { X } from "lucide-react";

export function MovieDetailsModal({ movie, onClose }) {
  // Escape কী দিয়ে modal বন্ধ করার accessibility support
  useEffect(() => {
    function handleKeyDown(e) {
      if (e.key === "Escape") onClose();
    }
    window.addEventListener("keydown", handleKeyDown);
    return () => window.removeEventListener("keydown", handleKeyDown);
  }, [onClose]);

  if (!movie) return null;

  return createPortal(
    <div
      className="fixed inset-0 z-50 flex items-center justify-center bg-black/60"
      onClick={onClose}
    >
      <div
        className="relative max-w-lg rounded-lg bg-white p-6 dark:bg-zinc-900"
        onClick={(e) => e.stopPropagation()}
      >
        <button onClick={onClose} className="absolute right-4 top-4">
          <X size={20} />
        </button>
        <img src={movie.poster} alt={movie.title} className="rounded-md" />
        <h2 className="mt-4 text-xl font-bold">{movie.title}</h2>
        <p className="mt-2 text-sm">জনরা: {movie.genres.join(", ")}</p>
      </div>
    </div>,
    document.body,
  );
}
```

`selected movie`-এর state রাখব `HomePage`-এ — লোকাল state হিসেবে, কারণ এটা শুধু এই পেজের modal-এর জন্যই দরকার, গ্লোবাল করার দরকার নেই:

### ধাপ ৮: লাইট অফ, ডার্ক অন — Theme Switch 🌗

থিম সুইচিংয়ের জন্য আলাদা একটা `ThemeContext` বানাবো, যা পুরো অ্যাপে theme state শেয়ার করবে এবং `localStorage`-এ persist করবে — যাতে পেজ রিফ্রেশের পরও ইউজারের পছন্দ মনে থাকে।

```jsx
// src/context/ThemeContext.jsx
import { createContext, useContext, useEffect, useState } from "react";

const ThemeContext = createContext(null);

export function ThemeProvider({ children }) {
  const [theme, setTheme] = useState(
    () => localStorage.getItem("theme") || "light",
  );

  useEffect(() => {
    const root = document.documentElement;
    root.classList.toggle("dark", theme === "dark");
    localStorage.setItem("theme", theme);
  }, [theme]);

  const toggleTheme = () =>
    setTheme((prev) => (prev === "light" ? "dark" : "light"));

  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      {children}
    </ThemeContext.Provider>
  );
}

export function useTheme() {
  const context = useContext(ThemeContext);
  if (!context) {
    throw new Error("useTheme must be used within a ThemeProvider");
  }
  return context;
}
```

`main.jsx`-এ পুরো অ্যাপকে `ThemeProvider` ও `CartProvider` দিয়ে wrap করে দেব (Provider-এর nesting order টেকনিক্যালি ম্যাটার করে না, তবে readability-র জন্য সবচেয়ে গ্লোবাল context বাইরে রাখাই ভালো):

```jsx
import { ThemeProvider } from "./context/ThemeContext";
import { CartProvider } from "./context/CartContext";

createRoot(document.getElementById("root")).render(
  <ThemeProvider>
    <CartProvider>
      <App />
    </CartProvider>
  </ThemeProvider>,
);
```

Tailwind v4-এর dark variant আমরা আগেই ধাপ ২-এ `@custom-variant dark (&:where(.dark, .dark *));` দিয়ে কনফিগার করে রেখেছি। ফলে `dark:bg-black dark:text-white`-এর মতো ক্লাসগুলো `<html>` ট্যাগে `.dark` ক্লাস থাকলেই অ্যাক্টিভ হয়ে যাবে — যেটা আমাদের `ThemeContext` টগল করে দিচ্ছে।

**Flash of Unstyled Theme (FOUC) ঠেকান:** React hydrate হওয়ার আগেই যেন সঠিক থিম apply হয়ে যায়, তার জন্য `index.html`-এ `<body>`-এর আগে একটা ছোট্ট blocking script বসিয়ে দিন:

```html
<script>
  (function () {
    const theme = localStorage.getItem("theme") || "light";
    document.documentElement.classList.toggle("dark", theme === "dark");
  })();
</script>
```

থিম সুইচার স্টাইলের রেফারেন্স ক্লাস — `styles.css`-এ যোগ করতে হবে:
